# Data model

Everything is stored on-device. This page describes every shape the app
persists or exchanges.

## Entities


Source of truth: [`src/types.ts`](../src/types.ts).

### `LoyaltyCard`

| Field             | Type      | Notes                                                |
|-------------------|-----------|------------------------------------------------------|
| `id`              | `string`  | Generated by `utils/createId.ts` (UUID).             |
| `name`            | `string`  | Display name; used for search and fallback initials. |
| `loyaltyNumber`   | `string`  | Raw string; barcode formatting normalises spaces/hyphens at render time. |
| `logoDataUrl`     | `string?` | Inline data URL (`data:image/...`). Missing → initials on accent colour. |
| `accentColor`     | `string?` | CSS colour; auto-derived from logo when absent.      |
| `note`            | `string?` | Free-form text shown under the title.                |
| `activationZones` | `ActivationZone[]?` | Empty / missing → card never surfaces as nearby. |
| `createdAt`       | `string`  | ISO-8601 timestamp, UTC.                             |
| `updatedAt`       | `string`  | ISO-8601 timestamp, UTC.                             |

### `ActivationZone`

| Field          | Type     | Constraints                         |
|----------------|----------|-------------------------------------|
| `id`           | `string` | UUID.                               |
| `label`        | `string` | Non-empty (trimmed).                |
| `latitude`     | `number` | `[-90, 90]`, finite.                |
| `longitude`    | `number` | `[-180, 180]`, finite.              |
| `radiusMeters` | `number` | `> 0`, finite. Default 250 on creation. |
| `createdAt`    | `string` | ISO-8601.                           |
| `updatedAt`    | `string` | ISO-8601.                           |

### `LoyaltyCardInput`

The form-facing shape — same as `LoyaltyCard` minus `id`, timestamps, and
`activationZones`. Zones are always added from the detail page after the card
exists.

## Storage

| Concern       | Key                 | Format              |
|---------------|---------------------|---------------------|
| Wallet        | `loyalty-cards:v1`  | `LoyaltyCard[]` as JSON |
| Brightness memo | (key handled inside `utils/screenBrightness.ts`) | Maps per-feature support state so prompts aren't repeated |

Defined in [`src/storage/cardsStorage.ts`](../src/storage/cardsStorage.ts) as
`CARDS_STORAGE_KEY`.

### Load / save semantics

- **`loadCards()`** returns an empty array when the key is missing, when JSON
  parsing fails, when the root isn't an array, or when every entry fails
  validation. Individual invalid entries are filtered out — the array is not
  discarded as a whole.
- **`saveCards(cards)`** serialises to JSON and writes the key. Failures
  (quota exceeded, disabled storage) return `{ ok: false, message }` so the UI
  can surface a persistent warning instead of silently losing data.

## Backup format (v1)

Exported via `createCardsBackup()`, imported via `parseCardsBackup()`.

```jsonc
{
  "version": 1,
  "exportedAt": "2026-04-16T10:12:34.000Z",
  "cards": [
    {
      "id": "…",
      "name": "Supermarché X",
      "loyaltyNumber": "3245676543210",
      "accentColor": "#0032b4",
      "note": "carte de Paul",
      "image": "icon-uuid-1",          // refers to icons[].id
      "activationZones": [ /* … */ ],
      "createdAt": "…",
      "updatedAt": "…"
    }
  ],
  "icons": [
    { "id": "icon-uuid-1", "name": "Supermarché X", "data": "data:image/png;base64,…" }
  ]
}
```

Rules:

- The icon payload is lifted out of each card and referenced by `image: id`,
  keeping the `cards` array human-readable.
- Backups written by older app versions that still carried `logoDataUrl`
  inline remain importable — `parseCardsBackup` accepts either `image` or
  `logoDataUrl` per card.
- `version !== 1`, missing `cards`, unknown field types, or orphan `image`
  references cause the whole import to fail with a descriptive message. No
  partial restore.

## Defensive parsing

Every persisted shape has a dedicated predicate (`isCard`, `isActivationZone`,
`isBackupCard`, `isBackupIcon`) in `cardsStorage.ts`. These validate both the
field presence and numeric ranges (latitude/longitude bounds, positive
radius). The goal is that malformed or future-schema data never reaches the
React tree.
